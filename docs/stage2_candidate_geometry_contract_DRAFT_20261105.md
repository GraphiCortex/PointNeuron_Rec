User disposition: earlier DraftB REJECTED; earlier DraftA HELD. Neither is
implemented/promoted. This document proposes a different comparison, with

## What the new diagnostic establishes

Original Stage0 union PASSED at90.42% segment F1_2 with2.39785x reference length.
The fixed radius2 compact union oracle scores88.52% at2 and clears the same
>=80% gate. This is reference-assisted geometric headroom,not learned accuracy.
NMS is diagnostic only,not adopted as the inference consolidation policy.

The compact ORIGINAL-LABEL training oracle loses substantial segment coverage
when suppressed nodes' incident edges are removed and surviving skip edges
retain their original negative labels. No links were repaired or relabeled.
This exposes a representation/target interaction: full-pool consecutiveness
does not necessarily mean consecutiveness after duplicate handling. A model's
learnability or optimal subset quality cannot be inferred from this oracle alone.

## Shared inference and data contract

Keep the fixed classical/Sato/broad-node pool and image-derived edge inventory;
no reference chooses an inference point,edge or root. Trace agreement remains
restricted to supplied annotations. References enter TRAINING labels and explicit
scoring only. Reference-empty,ambiguous/coincident projections and cross-fragment
relations remain unknown. Known-negative endpoint edges remain negative.
Reserved neurons are untouched; seven development neurons are repeatedly
inspected,with one scoring per final frozen model and no tuning afterward.

Node confidence must be named TRACE SUPPORT,not unique-representative probability.
A node within2 of the trace need not all survive in the final reconstruction.
Representative selection/consolidation and connectivity decoding must have
explicit responsibilities. A forest spanning every supported node can overtrace;
one-to-one resampled metrics and length ratio must accompany segment overlap.

For a future controlled contract comparison, both arms must use the SAME
image-only representative set and potential edges. Proposed policy for discussion:
radius2 greedy NMS ordered by saved image-guide response,source priority,
XYZ/index. NO oracle probabilities at inference. This proposed image-only
ordering has not been tested or adopted; its oracle headroom would need a
separate predeclared CPU check before using it. No rebuilding or remapping of
edges is silently authorized; if the induced graph lacks opportunity,discuss
candidate-recall work first. The current88.52% uses ORACLE ordering and is not
that image-only check.

## Proposed contract arms

**C0: original dense-pool adjacency labels, mapped to the common representative
graph.** Preserve the original consecutive-chain/path<=32 rules and unknowns;
apply no mask revision. Suppressed candidates no longer enter inference,but
their original effect on edge labels remains. This is the fixed historical
supervision control,not a claim that it is the right target after consolidation.

**C1: representative-conditional adjacency labels.** On the exact SAME fixed
image-only representative graph,define positive edges using consecutive retained
unambiguous trace-positive groups on a reference chain/path<=32. Intervening
suppressed candidates do not make an edge negative. Retain original projection
tie/coincidence/fragment and junction-ownership unknown semantics; no reference
creates missing potential edges or moves a point. Node support tolerance2,
tie distance.25,projection separation.5,path bound32 remain prospective constants
for comparison,not selected from development. Junction membership must be
derived only for labels on the actual retained representatives,with missed
junctions disclosed. Radius remains unsupervised. This target is adjacency
conditional on a declared representation,not geometric labels for every on-curve
skip. It does not revive rejected DraftB or release held DraftA.

Even C1 is not a complete uniqueness contract: radius2 NMS can retain points
on opposite sides of one curve,and adjacency groups may still contain several
supported nodes. Candidate-geometry features do not automatically turn support
labels into representative labels. Node/edge subset responsibility and residual
branching/multiplicity need discussion before implementation.

Both arms require actual implementation and user agreement before training;
neither label contract is generated by this diagnostic. Other alternatives
remain discussable; no contract is chosen by its training oracle score.

## Candidate-geometry features: image-only definitions, no implementation

- Intervening-candidate count: number of OTHER candidates with orthogonal
  projection strictly inside the potential segment and perpendicular distance
  <=1 native voxel. Count ALL candidates,not reference-positive candidates.
  Provide counts on the common pre-consolidation pool and retained graph,
  plus source-flag counts. Exclude endpoint indices and endpoint projection ties.
  The previous audit's reference-positive witness count is NOT an inference
  feature and must never be copied into a feature packet.
- Local spacing: endpoint nearest-neighbor distances and median distance among
  up to6 nearest other candidates on the same declared candidate set; include
  edge length divided by mean endpoint spacing,with explicit zero/missing flags.
  These distinguish a long skipped link in a dense region from a comparable
  link in a sparsely sampled branch. No reference arclength/projection is a feature.
- Keep agreed image/Sato/raw intensity/path-cost,direction/curvature,source flags,
  raw-vote support and optional frozen PointNeXt features. Straight Sato cost
  and actual geodesic cost remain distinct. No SWC branch/component identity,
  reference distance or true node/edge label enters features at inference.
- If confidence-weighted counts are later proposed,use training-fold out-of-fold
  predictions,never true labels masquerading as confidence. No such stacking
  mechanism is implemented or adopted by this draft.
