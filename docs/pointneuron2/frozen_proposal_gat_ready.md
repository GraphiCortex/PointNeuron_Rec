## Research question and deliberately easier control

Can the existing native GATv2 prototype learn correct connections between the
useful nodes already generated by the balanced PointNeXt/Transformer model?

This isolates connectivity. It does not solve automatic node selection or
establish full reconstruction quality, generalization, attention superiority
over a simpler edge head, or improvement over PN 1.0. It is one training seed on
four crops from three training neurons; no development/test data enter.

The automatic architecture is unchanged. Only this diagnostic bypasses the
confidence cutoff, using **saved assignment membership** to select 6/12/16/418
queries. Original query IDs determine node order, never reference target order.
Coordinates, radii, local coordinates, raw decoder features and learned
confidence logits stay frozen. The source is the stronger incomplete balanced
joint fit at update 4,000, not the subsequent frozen-confidence head.

The scorer receives the existing 133-dimensional node input and geometric edge
attributes. Reference target coordinates, IDs, roles and adjacency do not enter
the scorer. Oracle selection itself uses reference knowledge and is explicitly
not a deployable inference policy. Saved confidence remains a scorer input;
only decoding uses neutral node logits to retain every oracle-selected node.

## Diagnostic supervision change

The ordinary graph supervisor masks edges touching assignments displaced more
than two voxels. In this control, the saved assignment supplies correspondence
for every selected node, including the 14 dense misses at 2.011–2.596 voxels.
This **deliberately omits that placement mask only in the isolated runner**.
It tests learning connections on imperfect learned coordinates; it does not
silently relax production supervision or its trust tolerance.

Required reference adjacency is positive. Nonadjacency within one full-reference
tree is negative. Candidates between different/unknown full-reference trees
remain unknown and are masked from loss. An unknown edge selected by the decoder
is reported as inconsistent with the supplied reference graph, not certified
biological background. All candidates in these four prepared graphs happen to
have known labels; no unknowns are converted into negatives.

Candidates are rebuilt from retained coordinates alone using the existing
symmetrized 16-neighbour union eight-voxel-radius rule. This is different from
filtering the old 512-node candidate set: removing distractors can change nearest
neighbours. All required edges are available in the prepared graphs.

## Fixed fit, success and stopping rules

Use the existing **native-PyTorch prototype**, not an established official GATv2
benchmark reproduction. Fresh seed zero, two 128-channel layers, four heads,
LayerNorm, no dropout or BatchNorm, and a symmetric edge head: **119,041 trainable
parameters**. Only GATv2/stem/edge-head parameters train. Phase 1, PointNeXt,
Transformer, proposals and assignments remain frozen.

AdamW LR .001, weight decay .0001, clip ten, no scheduler/augmentation, one crop
per update in the declared cyclic order. Each crop uses the existing balanced
positive/negative edge BCE; unknowns are excluded. These are declared new-stage
settings, not a matched optimization comparison with the joint proposal fits.
Cap at **4,000 total updates**, or 1,000 updates per crop. Evaluate
0/500/1,000/2,000/4,000. No automatic early winner selection, extension, threshold
search, node cleanup, image tracing or whole-model unfreezing.

Primary diagnostic success requires the **decoded undirected edge set to equal
the supplied reference edge set on every crop at terminal update 4,000**. Report
missing/extra connections, all vertex degrees, junction incidence and components.
Matching degree/component counts alone cannot pass a rewired graph. Scores use
the fixed .5 edge cutoff and existing score-thresholded Kruskal forest decoder.
Independent positive misses, known-negative acceptances and unknown acceptances
are reported separately. Correct decoding can reject a high-scoring wrong cycle
edge, so the independent edge-classification gate is a separate diagnostic.

Every saved evaluation exports/reloads an SWC and verifies retained nodes,
connections, components, coordinates and floored radii. Root choice and generic
type are serialization conventions, not learned biological identity.

Geometry is scored against continuous reference segments clipped to the exact
target crop box, using the existing arclength-weighted midpoint quadrature at
at most .5 voxel. Correct connections on frozen coordinates give 100% precision/
recall within two voxels on the smaller crops and **98.77% / 97.98%** on the
dense crop. All reach 100% at six voxels. These are reference-connected
feasibility results, not learned scores. At graph success, geometry should
reproduce that fixed-coordinate result; geometry cannot be repaired by this fit.

Failure means this declared scorer/loss/optimizer/budget did not recover the
reference graph on the simplified fixed task. It does not prove the GATv2
function class incapable or justify a larger model automatically. Success
supports connectivity learnability conditional on oracle-selected nodes; it
does not resolve the real selector, crop merging or automatic full-neuron SWC.
Review the failure location before another run. Stop on nonfinite values,
cache/source changes, unsupported deterministic GPU operations or reload/export
failure. Never switch backend, relax tolerances or retry silently.
